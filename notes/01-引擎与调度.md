# 01 · 引擎与调度

## 入口：examples/offline_inference.py

```python
launch_dp(main, dp_size)          # 多 DP rank 各跑一份 main
create_llm(...)                   # 并行拓扑由 --ep/--dp/--cp 组成
llm.generate(prompts=..., sampling_params=..., ...)
```

要点：

- `world_size = dp × cp`，且必须整除 `ep`（MoE 专家按 EP 切）。
- 默认开 EPLB（专家负载均衡）与 `DEEPINFER_BATCH_INVARIANT=1`（批不变推理，仅 NVIDIA）。
- `lookahead_tokens=min(1, DEEPINFER_USE_NEXTN_DECODE)`：投机解码草稿长度，默认 5。
- 输出统计：`accept_rate`（draft 接受率）与 `decode_ppl` 由
  `RequestOutput.draft_tok / accept_tok / token_logprobs` 聚合（`offline_inference.py:82-86`）。
  这两个指标就是评估投机解码与模型质量的日常仪表盘。

## step() 主循环（llm_engine.py:860-959）

```python
def step(self):
    # 1) schedule:cpp —— C++ 调度器产出 seq_metadata_list + scheduler_outputs
    #    （同一调用顺便释放已完成序列）
    # 2) schedule:clone —— 调度器要求的 clone/zero states/blocks（抢占、YoCo 相关）
    #    在默认流上执行，unpins 登记到 DeferredRelease
    # 3) multi_modal_fetch —— 多模态 worker 异步产图；坏图直接 abort 请求
    # 4) _execute_model_async_step —— worker.execute_model_step，异步发射
    # 5) post_process —— 处理输出/统计，把 forward 与 sample 两个 CUDA event
    #    的耗时回填给 C++ 调度器（update_mtp_runtime），用于置信度调度
```

设计要点逐个说：

### 资源池化与延迟回收

`DeferredRelease`（67-119 行）回收本步要释放的资源，在下一次的
`pre_sampler_sync` 时释放——与 GPU 计算 overlap。对象池
（`RequestOutputPool`/`SequenceMetadataPool`）保证稳态不触发分配器。
注释原话："延后一轮释放 step 产出的资源，保证调用方读完。"

### 结构化输出的防御式容错（910-928 行）

最后一个 prefill chunk 上，若 SO（structured output）簿记正常就置
`so_status = 1`；否则**只杀当个请求**：置 `FINISHED_SO_FAILED` 让
process_outputs 当步回收。注释解释了为什么不能置 -1 走 sampler 早退——
`_get_so_mask` 快路径可能吞掉 -1。工业级代码的容错粒度值得学：
局部失败不升级为全局故障。

### KV cache 落盘钩子（930-937 行）

`do_copy_state` + `copy_state_event`：PD（prefill/decode）分离预留的
状态拷贝路径。README 说了分离部署未开源，但引擎侧钩子都在。

## C++ 侧有什么（csrc/engine/）

| 文件 | 职责 |
|---|---|
| `scheduler.hpp` | 调度决策（schedule 循环、抢占） |
| `zos.{hpp,cpp}` | zero-overhead scheduling：在途请求状态、异步步骤 |
| `block_manager.hpp` | KV 块与 state 序列的块管理（pin/unpin） |
| `sequence.hpp` / `outputs.hpp` | SequenceMetadata / RequestOutput 数据结构 |
| `prepare_sample.cpp` | 采样准备 |
| `input_metadata/prepare_tensor_input_v4.cpp` | V4 模型输入张量装配 |
| `mtp_varlen.hpp` | MTP 变长批处理 |

Python 通过 `from deepinfer._C.engine import ...`（pybind）拿到这些类型。
读法建议：先读 Python 的调用面（`llm_engine.py` 顶部 import 列表），
再按图索骥去 C++ 找实现。

## 一帧的时序心智模型

```
CPU:  schedule → [clone 发射] → [execute 发射] → post_process（等 sample_end event）
GPU:  [上一步 sampler 同步] → forward → sampler → CUDA event 标记
```

CPU 侧每步都在为下一步铺路（资源回收、元数据装配），
GPU 侧永远有活干——这就是"零开销调度"的直观含义。
`LLMEngine.step` 的注释还交代了 RequestOutput 的生命周期契约：
"RequestOutput will be automatically released in the next step() call；
要跨步保留必须 `pool.clone()` 后 `pool.release()`。"
