# 00 · 总览与阅读路线

> 精读对象：[deepseek-ai/DeepInfer](https://github.com/deepseek-ai/DeepInfer) main 分支（2026-10-27 快照）。
> DeepInfer 是 DeepSeek 生产级推理框架，2026-10-16 开源，Apache 2.0，基于 vLLM 改造。

## 一图看懂分层

```
examples/offline_inference.py      ← 用户入口（LLM 离线批量推理）
        │
deepinfer/entrypoints/  LLM        ← 薄封装
        │
deepinfer/engine/llm_engine.py     ← Python 编排层（step 主循环）
        │
        ├── deepinfer._C.engine    ← C++ 核心：Scheduler / BlockManager /
        │     (csrc/engine)          SequenceMetadata / 零开销调度 zos
        │
deepinfer/worker/                  ← GPU worker 进程（driver + 多 rank）
        │
deepinfer/model_executor/          ← 模型执行：models/ layers/ input_metadata/
        │
csrc/ + layers/tilelang_ops/       ← CUDA / TileLang 算子 + pybind
```

**读码前必须建立的判断**：Python 侧只是编排，真正的调度决策、内存块管理、
输出池都在 C++（`deepinfer._C.engine`，源码在 `csrc/engine/`）。
想看懂"零开销调度"，得去 `csrc/engine/scheduler.hpp`、`csrc/engine/zos.{hpp,cpp}`、
`csrc/engine/block_manager.hpp`。

## 这次开源了什么、没开源什么

开源的（README 明确列出）：

- 优化内核 + 模型/采样器运行时
- 并行：Attention DP / balanced CP、MoE EP + EPLB
- DSpark 与置信度调度验证（投机解码）
- SWA 有界回放（YoCo 截断）
- 异步调度（零开销 batch 调度器）、批不变推理、确定性采样、结构化输出

**没有**开源的：

- KV cache 系统（引擎里的 BlockManager 只是骨架配套，完整生产版未放出）
- VE/Prefill/Decode 分离部署（引擎侧功能大部分已实现）
- 跨副本负载均衡（prefill/decode 两个维度）

硬件要求：NVIDIA SM100（B200/GB200 档）或华为昇腾 950；Linux + Python 3.12 +
CUDA 13 / CANN 9.2。**没有消费级 GPU 就只能读码**——这正是本仓库 `mini_infer/`
存在的意义。

## 推荐精读顺序

| 步骤 | 文件 | 看什么 |
|---|---|---|
| 1 | `examples/offline_inference.py` + `_config.py`/`_launch.py` | 数据怎么进来，并行拓扑怎么拼 |
| 2 | `deepinfer/engine/llm_engine.py` `step()` | 一帧怎么跑完（Python 视角） |
| 3 | `csrc/engine/scheduler.hpp`、`zos.hpp/cpp`、`block_manager.hpp` | C++ 侧调度真相 |
| 4 | `deepinfer/model_executor/models/deepseek.py` `forward` | 模型怎么拼装 |
| 5 | `v4_modules/attn.py`（对照 `yoco.py`、`mla_attn.py`） | 注意力与 KV 共享 |
| 6 | `v4_modules/moe.py` + `mlp.py` + `model_executor/eplb/` | MoE 与负载均衡 |
| 7 | `mtp/dflash.py` + `layers/sampler.py` | 投机解码与采样 |
| 8 | `layers/tilelang_ops/`、`csrc/` | 算子层，配合官方内核仓库 |

对应笔记：01 引擎（步骤 1-3）→ 02 模型（步骤 4-5）→ 03 MoE（步骤 6）
→ 04 投机解码（步骤 7）→ 05 算子（步骤 8）。

## 工程上最值得偷师的三个习惯

1. **资源全池化 + 延迟回收**：`RequestOutputPool` / `SequenceMetadataPool`，
   本步资源推迟到下一步 `pre_sampler_sync` 释放，与 GPU 计算 overlap，稳态零分配。
2. **防御式容错只杀局部**：结构化输出簿记出错时只杀当个请求，且注释把
   "为什么置 -1 可能被快路径吞掉" 讲清楚（`llm_engine.py:910-928`）。
3. **数值回归基线**：PPL 基线存 `tests/models/offline_decode_ppl.json`，
   逐样本精确对比；任何改动先跑基线再合并。个人项目也值得抄这套。
