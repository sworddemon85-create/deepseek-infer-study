# 05 · 算子生态

> DeepInfer 的性能来自一整套自研内核。README 的 feature 列表点名了：
> FlashMLA、DeepGEMM、DeepEP、TileKernels、DeepSelect，
> 以及自写 TileLang 内核（`deepinfer/model_executor/layers/tilelang_ops/`）。

## 官方内核仓库速览

| 仓库 | 干什么 | 在 DeepInfer 里的入口 |
|---|---|---|
| [FlashMLA](https://github.com/deepseek-ai/FlashMLA) | MLA 高效注意力内核（Hopper/Blackwell） | attention backend |
| [DeepGEMM](https://github.com/deepseek-ai/DeepGEMM) | FP8 通用矩阵乘（含 ue8m0 scale） | `use_fp8_gemm` 的 Linear |
| [DeepEP](https://github.com/deepseek-ai/DeepEP) | 专家并行 all-to-all 通信 | EP dispatch/combine |
| [TileKernels](https://github.com/deepseek-ai/TileKernels) | TileLang 写的算子库 | `tile_kernels.*` |
| [DeepSelect](https://github.com/deepseek-ai/DeepSelect) | 选择类算子（如 top-k） | `from deep_select.interface import topk`（sampler.py:12） |

## 仓库内怎么组织

- `deepinfer/model_executor/layers/tilelang_ops/`：TileLang 内核封装，
  按硬件再分 `cuda/` 与 `asc/`（昇腾）两套实现——同一 Python 接口，
  双后端各自编译。
- `csrc/`：CUDA/C++ 绑定层（`pybind.cpp` 暴露给 `deepinfer._C`），
  含 `engine/`（调度 C++ 侧）、`graph_timer/`、`utils/`。
- `deepinfer/npu_ops/`：昇腾专用算子。

双硬件支持的做法值得注意：模型代码（`v4_modules/`）完全不含
硬件分支，硬件差异全部下沉到 layers/tilelang_ops 与 npu_ops。

## 数值基线的工程实践

`tests/models/offline_decode_ppl.json` 按"平台/负载"分键存 PPL 基线，
逐样本精确对比：

- 改了任何数值路径 → 先跑 `refresh_offline_decode_ppl.py` 看差多少
- 多节点跑基线时按节点分片刷新/校验，跨节点文件锁防覆盖
- 长上下文（16389 输入 / 4096 输出 / nextn=5）单独一个测试文件

这套"逐样本精确基线"比"容差断言"严格得多——适合移植到任何
对数值敏感的项目。

## Benchmark 设计速记（examples/README.md 的精华）

- prefill 与 decode 解耦：`--prefill_batch_size` 只管 prefill chunk，
  `--decode_num_requests` 只管 decode batch，两者共享前缀 KV
- 三指标：prefill throughput（tokens/s/GPU）、decode avg_SPS、
  decode throughput（按 `1 + nextn` 全接受计账）
- 测量窗口避开 LB 刷新与 profiler 残留减速（profiler 退出后有
  ~7-11% 残留减速，所以测量必须排在 profiler 之前）
- `sweep/run_sweep.sh` 扫参 → `results.jsonl` → `plot_pareto.py`
  画吞吐-延迟 Pareto 曲线

## 学习路线建议

读算子层前先补两个背景：
1. MLA 的数学（推荐直接读 FlashMLA 的 README 与 DeepSeek-V3 论文 §2.1）
2. TileLang 是什么（Python DSL 写 CUDA，TileKernels 仓库有大量例子）

然后按"Python 封装 → kernel 源码"的顺序读：先 `tilelang_ops/gather.py`
这类简单的，再读 FlashMLA 的复杂内核。
