# 02 · 模型架构：DeepSeek-V4.1-Flash

> 核心文件：`deepinfer/model_executor/models/deepseek.py`（59-248 行）、
> `decoder_layer.py`、`v4_modules/attn.py`、`v4_modules/yoco.py`。
> 名词不懂先查 [glossary.md](glossary.md)。

## DeepseekModel.forward 骨架

```python
embed_tokens
  → 逐层 DeepseekDecoderLayer：
      ├─ YoCo 边界层（i == cfg.n_prefill_layer）处切换 metadata 视图
      │    （compact 视图：只保留需算到底的行；mask 视图：另一路）
      ├─ 每层把 dflash_input（目标层特征）攒出来
      └─ Engram n-gram 哈希嵌入经 embed_hook 注入
  → HCHead（可选 hidden 压缩头）
  → output_norm
```

三个贯穿全模型的运行时机制（`deepseek.py:154-248`）：

1. **CrossLayerRuntime**：跨层持有的运行时值（shared_hidden / pre_rope_kv /
   topk）逐层传**同一引用**，由各层原地写入——避免每层重新计算共享量。
2. **YoCo 边界切换**：compact 模式下在 `n_prefill_layer` 处把
   `input_metadata` 切成 consumer 视图，DFlash 目标层与 Engram 层都必须
   整体处在边界同一侧（构造时有 assert 校验，118-138 行）。
3. **DFlash 特征攒取**：`dflash_input` 是主模型各目标层 hidden 的拼接，
   decode 时随主模型 CUDA graph 一并捕获（220-223 行）。

## 注意力：V4Attention（v4_modules/attn.py:228 起）

V4.1-Flash 的注意力是"全家桶"式混合，每个层可能有：

| 组件 | 说明 |
|---|---|
| Q 低秩路径 | `q_a`（LoRA 式降维）→ RMSNorm → `q_b`（升维到 n_heads × qk_head_dim） |
| KV 压缩 | `kv_compress_ratio`：KV 投影带 Gate + 低秩压缩；`is_c1` 表示不压缩 |
| SWA + sink | 滑窗注意力 + attention sink（`sink_mode == "swa"`），配合 prefill 有界回放截断 |
| MQAIndexer | 稀疏注意力索引器：先用 index attention 选 top-k token，再主注意力（延续 V3.2 DSA 思路） |
| KV/索引共享 | `SharedLayerTopology`：KV 源层与索引源层可以解耦，不同层共享同一份 KV 或索引 |

### 投影融合的工程手法（278-373 行）

推理框架的经典优化在这个文件里随处可见：

- `q_b` 升维与 indexer 的 q 投影**权重合并成一次 GEMM**（`_init_q_projections`）。
- 来自当前层 hidden 的多个投影（KV、index weights）合并为
  `current_hidden_proj`，布局记录在 `current_hidden_proj_layout`。
- YoCo consumer 层的 KV 来自 shared hidden（不是本层 hidden），所以必须
  单独走 `shared_hidden_kv_proj`——"能 fuse 就 fuse，但输入源不同不能 fuse"
  这个约束在注释里反复出现。

### 量化

SWA KV 走 FP8（e4m3）+ `ue8m0` scale format（`_prepare_swa_kv`，
402-417 行）。这是 DeepGEMM 生态的标准格式。
